# 本地记录、迁移与隐私

桌面版由 Rust 负责剪贴板采集和持久化，React 只读取带版本号的快照、发送操作。窗口隐藏后仍每 500 ms 检查一次剪贴板；应用完全退出后停止采集。浏览器开发模式使用独立示例缓存，不提供系统采集。

## 数据存放

应用数据目录中包含 `history.sqlite`（SQLite WAL）、`images/`（按像素摘要命名的 PNG）和 `backups/`（迁移备份）。标准位置：

- Windows：`%APPDATA%\com.clipjar.desktop`
- macOS：`~/Library/Application Support/com.clipjar.desktop`
- Linux：`$XDG_DATA_HOME/com.clipjar.desktop`，通常为 `~/.local/share/com.clipjar.desktop`

设置页显示数据库、日志、图片及迁移备份的文件大小。图片不再经过 localStorage 的 JSON/base64 往返。单次采集上限为 1600 万像素或 1 MiB 文字，超限不截断覆盖旧内容。收藏不占普通历史条数，也不受自动到期清理影响；收藏图片可能持续占用磁盘。

这些文件含剪贴板内容，未加密。备份整个目录时请先完全退出 ClipJar；只复制主数据库可能遗漏 WAL 中已提交的数据。

## 首次升级

首先把旧 `clipjar-storage` 原文原子写入 `backups/legacy-<摘要>.json`，再解析图片、在事务内导入记录与设置。事务提交成功后，前端才删除旧缓存。迁移失败会保留原缓存和已写入的备份，并提供重试。

相同文字或相同像素的图片合并为一条记录，保留收藏、标签和备注；不同备注合并保留。旧版本已经省略的图片无法凭空恢复，其记录会保留并在复制时提示缺失。

如需人工恢复迁移备份：先退出应用并另存整个数据目录；在独立测试配置中将备份 JSON 作为旧缓存重新导入。不要直接覆盖运行中的 SQLite 或 WebView 文件。备份用于故障恢复，目前没有面向用户的导入按钮。

## 撤销、清空与暂停

- 单条删除可在 10 秒内撤销，期限在重启后仍有效。重新复制相同内容会恢复该条记录并使旧撤销失效。
- “清空普通历史”保留收藏；“清空全部数据”删除普通记录、收藏、图片和迁移备份，均需在设置页再次确认。
- 暂停可选 15 分钟、1 小时或手动恢复，状态持久化。暂停时不读取系统剪贴板；恢复后只把当前内容作为基线，后续新复制才记录，避免补录暂停期间的敏感内容。
- 全部清空会截断应用数据库 WAL，但不会整理旧 WebView 数据库，也不承诺磁盘介质上的取证级擦除。

## 验证

```sh
npm test
npm run build
npm run test:history
npm run test:browser
npm run tauri -- build --debug --no-bundle
npm run test:native
```

最后一项需要真实桌面会话，使用独立临时数据目录，会写入测试剪贴板内容。它检查原生文本/图片剪贴板、隐藏窗口采集、快捷键注册、暂停恢复。浏览器测试使用命令和事件模拟，不能代替原生测试。

`.github/workflows/ci.yml` 在 Windows 和 macOS 上运行这些检查，并上传截图及原生日志。新增工作流不等于这些平台已经通过；请查看对应提交的 Actions 结果。
